# 승인과 무료 Google 환경 준비

상태: 2026-10-14, 사람인 신청 완료·승인 대기(사용자 보고). 고용24 일반 채용정보 API는 MVP에서 제외한다. 사용자가 bound Apps Script에 파일을 복사하고 수동 실행했으며 제공된 Google 로그에서 `HOLD_APPROVAL_CONFIGURATION`·수집 0건·실행 완료를 확인했다. 실제 키 호출·공고 저장·예약 실행은 미검증이다. 키·개인 이메일·프로필 원본은 이 문서나 GitHub에 입력하지 않는다. 승인 후 파일럿은 [saramin-operations.md](saramin-operations.md)를 따른다. 아래 readiness는 별도의 환경 점검 경로다.

## 완료한 사람인 신청과 승인 대기

[공식 신청](https://oapi.saramin.co.kr/join)은 완료했으므로 중복 신청하지 않는다. 아래 목적문은 신청 준비 당시의 참고 기록이다. 승인 결과와 실제 데이터 이용 허용 범위를 확인한 후 연결한다. 프로젝트 소스 공개와 API 키·개인정보·수집 데이터 공개는 구분한다.

복사할 이용목적 초안:

> 개인 구직 활동을 돕기 위한 비상업용 채용정보 자동화 프로젝트입니다. 공식 API가 허용한 직무·지역·급여·마감 정보를 하루 제한된 횟수로 조회하고, 중복 제거와 조건 비교 후 본인만 접근하는 Google Sheets에 저장하며, 본인이 동의한 주소로 일일 요약을 받고자 합니다. 재판매·유료 제공·비공식 본문 수집은 하지 않습니다. 허용된 공고 메타데이터를 무료 AI 요약에 활용할 수 있는지와 저장기간·메일 재전달·출처 표시 조건도 확인받고자 합니다. 실제 이력서·개인 프로필은 무료 AI에 전송하지 않습니다.

신청 전 확인할 질문: 개인 비상업 프로젝트 신청 가능 여부, URL 요건, 호출 한도의 계정/키 집계, 페이지 전체 조회, 본문 제공 여부, 비공개 보관기간과 삭제 의무, 본인 요약메일, 외부 AI 전송 허용 범위. 직접 문의가 필요하면 위 내용을 본인이 보내며 이번 작업에서 연락을 대신 발송하지 않는다.

승인 후 [발급 안내](https://oapi.saramin.co.kr/guide/1)에 따라 앱을 등록한다. 키 값은 채팅·Git·프런트 환경변수에 붙여 넣지 않는다. 승인 여부와 허용 범위만 공유하고 키는 다음 연결 작업에서 승인된 서버 설정에 직접 넣는다. 준비된 현재 probe는 **키 없는 인증 요구 확인용**이며 키를 추가하는 수집 CLI가 아니다.

## 고용24 MVP 제외

사용자가 개인회원으로 일반 채용정보 API를 이용할 수 없음을 확인했다. 이 MVP에서 신청·연결·인증 probe를 진행하지 않는다. 타인 키·기업회원 가장·대체 스크래핑을 사용하지 않는다.

## 비공개 Sheets와 Apps Script 점검

본인 Google 계정으로 새 Google Sheets를 만들고 공유의 일반 액세스를 **제한됨**으로 유지한다. 웹에 게시·익명 보기·누구나 웹앱을 켜지 않는다. 실제 이력서·급여·API 키 없이 빈 시트로 시작한다.

시트에서 확장 프로그램 → Apps Script를 연다. [Bootstrap.gs](../automation/apps-script/Bootstrap.gs)를 스크립트 편집기에 복사한다. 프로젝트 설정에서 매니페스트 표시를 켜고 [appsscript.json](../automation/apps-script/appsscript.json)의 Asia/Seoul·V8·최소 scope를 대조한다. 이번 점검 scope는 현재 시트와 트리거 관리뿐이며 외부 URL Fetch·이메일·AI 권한을 요청하지 않는다.

`recordAutomationReadiness`를 본인이 수동 실행하고 필요한 Google 권한을 검토·승인한다. `AutomationReadiness` 탭에 날짜·승인 대기 상태·수집 0건이 생기는지 확인한다. 같은 날 두 번 실행해 행이 늘지 않는지 확인한다. 승인 플래그나 키를 입력할 필요가 없다.

수동 점검이 통과하면 `createDailyReadinessTrigger`를 수동 실행한다. 트리거 화면에서 함수·매일·Asia/Seoul·오전 9시대를 확인한다. 이는 **예약 실행환경 점검용**이며 공고 수집이 아니다. 같은 함수를 다시 실행해 트리거가 중복되지 않는지 확인한다. 다음 실행 기록과 시트 날짜로 실제 Google 예약 실행을 검증한다. 필요 없으면 이 함수의 트리거만 Google 화면에서 제거한다.

본인 인증·Google OAuth 동의·외부 약관 수락은 본인이 진행한다. 코드 파일이 준비됐다는 이유로 Google 프로젝트·시트·트리거가 생성된 것은 아니다. 이상이 생기면 키나 계정정보 대신 오류 종류·실행 상태만 공유한다.

## Gemini는 마지막에 확인

API 공급자의 AI 전송 허용 범위와 [Gemini 약관](https://ai.google.dev/gemini-api/terms)을 확인한 뒤 [Google AI Studio](https://aistudio.google.com/)에서 무료 계층의 프로젝트·키·실제 모델 한도를 확인한다. 결제 계정 활성화·카드 등록·유료 모델 전환은 하지 않는다. 실제 경력·희망 연봉·이력서 원본을 입력하지 않는다. 초기 시험은 합성 조건과 허용된 비개인 공고 정보만 사용하며 무료 모델이 없으면 보류한다.

## 연결 작업을 시작할 때 필요한 확인

사람인 승인 여부와 허용 범위를 확인한 뒤 [수집용 패키지와 비공개 설정](saramin-operations.md)으로 소량 수동 파일럿을 진행한다. 실제 필드·페이지·비공개 저장·재실행을 확인한 다음 예약을 설정한다. 원문 응답은 공개 fixture로 옮기지 않는다. 메일 수신 동의·발송 worker·outbox 검증과 React 소유자 인증 연결은 후속 작업이다. 승인 거절 시 [공식 알림메일 대안](official-email-fallback.md)을 따른다.
