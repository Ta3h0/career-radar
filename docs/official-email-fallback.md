# API 거절 시 공식 알림메일 대안

2026-10-14 공식 자료 조사. API 승인을 우회해 같은 API를 호출하거나 공고 HTML을 크롤링하는 대안이 아니다. **아직 실제 메일 수신·받은메일 접근·자동 파싱은 검증하지 않았다.**

사람인 [개인회원 공식 도움말](https://m.saramin.co.kr/help-word/view?idx=533)은 ‘나의검색’의 저장 조건 기반 추천과 ‘AI 매치’의 활동 기반 추천 모두 이메일/앱 알림 설정을 제공한다고 설명한다. 우선 나의검색에 직무·지역 등 좁은 조건을 저장하고 이메일 수신을 켜는 경로를 시험할 수 있다. API 키 없이 추천을 받는 서비스지만 발송 빈도·전체 신규 공고 커버리지·메일 전문 제공은 보장할 수 없다.

## 준비와 검증 순서

1. 본인이 사람인에 로그인해 나의검색/이메일 수신 설정을 확인한다. 전용 비공개 수신함 또는 Gmail 라벨로 공식 채용 알림만 구분한다. 실제 받은 메일이 있어야 다음 검증을 시작할 수 있다.
2. 메일 내용 보관·개인 자동 정리·요약·외부 AI 전달이 허용되는지 서비스 조건/안내를 확인한다. 메일을 받았다는 사실만으로 재배포·AI 전송 권리가 생기지 않는다.
3. 사용자가 동의한 전용 계정/라벨에 한해 Gmail 읽기 연동을 검토한다. 실제 발신 도메인과 메시지 인증 결과를 확인한다. 표시 이름/From 문자열만으로 신뢰하지 않는다. 이 작업에서 Gmail 권한을 추가하거나 받은메일을 읽지 않았다.
4. 공식 직접 공고 링크와 공개 ID만 추출한다. 개인 이름·수신 주소·개인 추천 식별자·전체 MIME/첨부는 저장/로그/AI 입력에서 제외한다. 첨부·이미지·수신 추적·단축/리디렉션 URL을 따라가지 않는다.
5. 메시지 ID의 해시와 공고 ID로 반복 처리를 방지한다. 링크 이외의 필드는 실제로 메일에서 확인되고 허용된 경우에만 별도 출처로 저장한다. API 수집과 출처를 섞지 않는다. 링크만 있으면 연봉/경력/본문은 미확인이다.

현재 `server/collectors/official-email.ts`는 **검증된 후보 URL 배열을 받는 순수 파서**만 준비했다. 동의/상위 발신 검증 없으면 보류하고, 허용된 직접 사람인 링크만 중복 제거한다. 테스트는 합성 링크뿐이다. 실제 MIME 구조, 발신 검증, 라벨 조회, Gmail 중복 상태 저장과 스케줄 연결은 미구현이다. 메일이 추적 링크만 제공하면 자동 추출을 보류하고 사람이 원문을 확인한다.

## 비용과 권한

[Gmail 라벨](https://developers.google.com/workspace/gmail/api/guides/labels)로 처리 범위를 제한할 수 있으나 [gmail.readonly](https://developers.google.com/workspace/gmail/api/auth/scopes)는 특정 라벨에만 한정된 접근 권한이 아니다. 일반 받은메일 전체를 읽을 수 있는 권한이므로 전용 계정이 유리하고, 별도 OAuth 동의/공개 앱 검증 필요 여부를 확인해야 한다. 현재 수집용 GAS 매니페스트에는 Gmail scope가 없다.

[Gmail API 비용 안내](https://developers.google.com/workspace/gmail/api/reference/quota)는 표준 사용을 추가 비용 없이 제공하지만 2026년 중 quota 초과 과금 도입 계획도 명시한다. 향후 정책을 다시 확인하고 결제 계정·초과 사용·한도 증액 없이 작은 예산에서 중단하는 방식만 검토한다. 무료가 불확실하면 연동을 보류한다. 먼저 공식 알림메일을 사람이 받는 경로만으로도 매일 사이트 방문을 줄일 수 있다.
