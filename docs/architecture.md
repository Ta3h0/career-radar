# Career Radar — 시스템 아키텍처 초안

작성일: 2026-10-14. 사람인 신청 완료·승인 대기. 고용24 일반 채용정보 API는 개인회원 이용 불가로 MVP 제외. 정규화·중복 제거·필터와 승인 차단 수집기, Google URL Fetch/Sheets journal/일일 트리거 어댑터를 준비했다. 공식 예시 재구성·모의 서비스 검증 후 사용자 제공 Google 로그에서 승인 전 보류·수집 0건을 확인했다. 실제 인증 수집·공고 저장/예약·AI·메일은 아직 없다. 현재 구현 한계와 실행 절차는 [saramin-operations.md](saramin-operations.md)를 따른다. 아래 분석·알림·React 연결 중 미구현 부분은 설계 초안이다.

## 구성과 데이터 흐름
```text
일일 예약 실행 (09:00 KST 목표, 실행 시각 지연 표시)
  → 사람인 공식 API 어댑터 (승인된 인증·쿼터만)
  → 원본 응답은 메모리 처리 → 정규화 → 출처 ID별 upsert
  → 사용자 필수 조건 필터 → 변경된 후보 분석 대기열
  → 무료 AI 어댑터 → 결과 스키마/근거 검증 → 적합도·신뢰도
  → 자동 저장 → 중복 방지 알림 outbox → 동의한 수신자 이메일

React + TypeScript UI ↔ 인증된 서버 API ↔ 저장소
                              ↕
                      수집/분석/알림 상태
```

## 프런트엔드와 서버 경계
프런트엔드는 목록·필터·상세·설정·저장 상태만 담당한다. 공급자 인증키, AI 요청, 이메일 발송, 예약 실행은 서버/백그라운드 작업에서 처리한다. 브라우저 타이머나 localStorage만으로 매일 수집·이메일·영구 저장을 구현했다고 간주하지 않는다.

현재 구조는 `src/domain`의 공유 타입, `src/features/dashboard`의 화면, `src/components`의 표시 컴포넌트, `src/styles`의 CSS다. 서버 계약은 `server/collectors/contracts.ts`, `server/pipeline/contracts.ts`다. 사람인 mapper와 pipeline/deduplicate·filter·prepare는 순수 함수다. `saramin-runner.ts`는 동기 I/O 포트로 페이지별 커밋·예산·한 번 재시도·시간창 재개를 처리한다. Google 어댑터는 같은 TypeScript 코어를 패키징해 사용한다. 브라우저에서 서버 코드를 import하지 않는다. 실제 수집·저장 서비스와 AI·발송 worker의 연결은 아직 없다. 모의 반복 처리를 라이브 전체 멱등성으로 해석하지 않는다.

## 공식 API 어댑터
| 영역 | 공통 계약 초안 |
|---|---|
| 입력 | 승인된 인증·필터·페이지/커서·최근 성공 체크포인트·실행 예산 |
| 출력 | 공고 목록, 다음 페이지 정보, 출처 시간대·필드 가용성·쿼터 상태 |
| 제한 | 문서화된 공식 endpoint만 허용, 임의 URL 호출·웹 HTML 수집 금지 |
| 실패 | 401/403은 인증/승인 필요로 중단, 429는 제한된 지연 후 보류, 5xx는 횟수 제한 재시도 |

사람인 필드는 공식 명세와 문서 예시로 매핑했고 실제 승인 후 표본과 대조해야 한다. 공식 주의사항의 일 공고 호출 최대 500건보다 작은 별도 예산으로 시작하고 계정별 의미를 확인한다. 고용24 계약/타입은 기존 확장 호환용이며 활성 수집기가 아니다. 페이지 이동·색인 지연으로 최신 등록분 완전 수집이 불가능하면 커버리지와 부분 수집을 표시한다.

## 정규화·중복 제거
- 출처 내부 키는 `(source, sourceJobId)`로 유일하게 관리하고 게시/수정/수집 시각을 구분한다. 페이지 중간 실패 후 체크포인트를 성공한 범위까지만 전진시킨다.
- 출처 간 중복 후보는 정규화 회사명·직무·지역·공고명·마감 정보로 비교한다. 확정 근거가 약하면 단순 삭제하지 않고 별도 후보 그룹으로 둔다. 출처 링크·ID는 모두 보존한다.
- API에 없는 정보는 null과 missingFields로 기록한다. 긴 원문과 개인정보의 저장 여부·보존 기간은 이용조건과 필요성으로 결정한다.
- 내용을 정규화한 해시가 바뀌면 분석을 다시 대기시킨다. 분석 캐시 키는 공고 내용 해시+사용자 조건 버전+모델/프롬프트/평가 규칙 버전이다.
- 종료/삭제 여부를 API가 제공하지 않으면 원문 상태를 확정하지 않는다. 오래된 공고에 마지막 확인 시각과 미확인 상태를 표시한다.

## 데이터 모델 초안
| 모델 | 핵심 필드 |
|---|---|
| Job | 내부ID, 제목·회사·지역·경력·고용형태·연봉 범위/단위, 마감·등록·수정·수집 시각, 내용 해시, 누락 필드 |
| JobSource | source, sourceJobId, 공식 URL, 제공 필드, attribution, 보관/처리 허용 범위 |
| Preferences | 희망·필수·제외 조건, 버전, 저장 시각. 직접 식별정보와 분리 |
| Analysis | jobId, 조건 버전, 적합도, 근거 배열(조건·출처 필드·발췌·해석), 누락 정보, 신뢰도·사유, 모델·프롬프트·규칙 버전, 시각·상태 |
| SavedJob | 사용자/공고, 저장 상태·시각 |
| Run | 유형, 출처, 시작·완료·실패·부분 성공, 체크포인트, 처리 수, 제한 사유 |
| NotificationOutbox | 수신자 참조, 일자/공고그룹 키, 동의 버전, 상태·시도 횟수·공급자ID |
| Delivery | 발송 키, 수신 확인이 아닌 공급자 접수 결과, 성공/실패/미확인 상태 |

개인정보는 별도 보호 영역에 두고 브라우저나 로그에 비밀을 노출하지 않는다. 계정이 여러 개로 확장되면 모든 읽기/쓰기에서 소유권을 확인한다.

## AI 어댑터와 신뢰도
공급자 중립 계약으로 정규화 공고의 허용 필드와 최소 사용자 조건만 전달한다. 고정 JSON 스키마로 요약·적합/부족/미확인 근거를 받고 서버에서 검증한다. 공고의 HTML·문구는 명령이 아닌 데이터로 격리하며 외부 도구 호출 권한을 주지 않는다.

공급자의 무료 모델/정책/쿼터·데이터 보관 조건은 도입 시 확인한다. Gemini 무료 계층은 후보지만 개인·기밀정보 제출 제한이 있어 실제 프로필 전송은 미승인 상태다. 익명화만으로 안전을 단정하지 않는다. 데이터 처리 요건이 충족되지 않으면 AI 분석을 보류하고 합성 데이터로 개발한다.

검증 실패는 제한된 재시도 후 실패/보류 상태로 저장한다. API가 정상 응답했더라도 근거가 원문과 일치하지 않으면 완료 처리하지 않는다. 신뢰도는 정보 충족·근거 검증·평가셋 결과로 설명하고 모델이 내놓은 숫자를 확률로 보장하지 않는다. 프로필·공고 변경 시 이전 분석임을 표시한다.

## 저장·예약·이메일
무료 영속 저장소와 예약 환경을 선택해야 한다. 로컬 예약은 컴퓨터가 켜져 있고 작업이 실행될 때만 동작한다. 클라우드는 무료 플랜의 휴면·실행 지연·DB 보존·이메일 한도까지 확인한다. 예산을 넘어서는 자동 승격은 금지한다.

실행 잠금과 runId로 동시 중복 실행을 방지하고 같은 입력을 재실행해도 상태가 안정되게 한다. 분석 저장과 outbox 생성은 가능한 경우 같은 트랜잭션으로 처리한다. 메일 발송은 outbox worker가 맡고 `(수신자 참조, 날짜, 공고 그룹/내용 버전)` 키를 중복 방지에 사용한다. 공급자가 idempotency를 지원하지 않아 발송 직후 연결이 끊기면 전달 여부를 미확인으로 두며 무조건 재발송하지 않는다.

메일은 사용자가 동의한 주소로만 전송한다. 발신 인증, 수신 거부, 보관 기간, 무료 한도 확인 전 실제 발송은 보류한다. 본문에는 허용된 최소 공고 정보와 원문 링크를 넣고 민감한 프로필·API 키를 넣지 않는다.

| 구성 | 선정 기준 | 현재 상태 |
|---|---|---|
| 호스팅/서버 | 무결제 무료 사용, 서버 비밀 보호, 요청 제한 | 미선정 |
| 저장소 | 무료 영속성·백업/복구·보존 기간·데이터 접근 제어 | 미선정 |
| 예약 | 일일 실행·중복 잠금·지연/실패 감지 | 미선정 |
| 공고 API | 신청 자격·승인·허용 활용·쿼터 | 실제 계정 미확인 |
| AI | 실제 무료 모델·비과금·개인정보/콘텐츠 처리 허용 | 미선정 |

0원 상한에서 처리할 수 없는 작업은 대기/중단한다. 유료 백업 공급자·신용카드 연결·체험 과금은 사용하지 않는다. 위 표 검증 전 운영 가능성이나 비용 0원 달성을 완료로 표현하지 않는다.

## 3단계 무료 자동화 후보와 검증 경계

[automation-feasibility.md](automation-feasibility.md)의 공식 API·Google 근거와 MVP 결정이 우선한다. 개인 사용자에게 고용24 접근이 보장되지 않고, 사람인 메타데이터에는 본문 반환이 확인되지 않았으며, 무료 Gemini에 개인 프로필을 바로 전송할 수 없다. 먼저 승인된 사람인 메타데이터·비공개 Sheets·비공개 규칙 비교·소유자 일일 요약을 목표로 좁힌다.

기존 readiness 코드와 별도로 `Collector.gs`·생성된 `Core.gs`는 소유자 비공개 bound Sheet, LockService, 요청 전 영속 예산 차감, 페이지 JSON journal, 중복 방지 시간 트리거를 준비한다. 코드 작성·패키징·서비스 모의 테스트까지만 완료했으며 Google 실배포는 아니다. journal에 공고·필터 결과에 따른 대기 항목·체크포인트를 함께 기록하고 재생한다. 현재 대기 구조는 완성된 알림 outbox가 아니며 발송/동의 정보와 AI 검증 worker는 후속 구현이다. 파일럿 용량/검색 범위 변경 제한을 운영 문서에 명시한다.

React 연결은 소유자 제한 HTML Service 내에서 React를 구동하고 google.script.run으로 승인된 서버 함수만 호출하는 경로를 우선 시험한다. localhost에서 google.script.run을 사용하거나 공개 시트·익명 JSON endpoint에 개인 조건을 내보내지 않는다. 번들/CSP·로그아웃/다른 계정 접근 차단을 실검증하기 전 연결 완료라고 주장하지 않는다.
